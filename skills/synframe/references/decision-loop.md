# v3.2 호스트 판단·실행 절차

이 파일은 §§6–16·21–27의 실행 표현이다. 신규 실행과 맥락 소실 후에는 필수
learning-contract.md 전체를 읽는다. 해당 세부 계약을 이 절차나 요약으로 대체하지
않는다. 호스트가 단일 논리적 Meta-Controller이며 코어는 의미적 판단을 생성하지 않는다.

## 시작과 목표 보존

기존 요청·맥락·자료에서 결과, 의무 수단, 제안 수단, 추론된 기능을 구분한다.
source_request의 정확한 인용에 안정 facet ID를 부여한다. GoalSpec.extensions의
`goal_alignment`는 facets(id/source_quote/interpretation/criterion_ids)와
preservation_rationale다. 성공 기준이 원래 목적을 충족하는지 의미적으로 대조한다.
답변 목차로 축소하지 않는다. 조언에 필요한 조사를 미래 구현 단계로 미루지 않는다.

사용자에게 추가 지식·설명·기술 판단을 요구하지 않는다. 기존 맥락과 가용 관측으로
해결한다. 불확실한 해석은 기존 근거와 공통 유효 범위로 처리하며 선호·권한을
만들어 내지 않는다. 실제 접근 불가라면 대체 경로를 조사해 정확한 영향을 보존한다.
자신의 목표 축소 교정은 GOAL_COMPILE/source_preservation_correction으로 원문·명시
제약을 보존한다. 실제 사용자 목표 변경에는 그 출처를 구분한다. 초기 criterion에
없어도 원문·Frame·기능·가정·선택에서 도출된 정보 요구를 받아들인다.

resume은 계약·코드·스키마 identity와 체크포인트, LearningTask, frontier, 미처리
발견, 역할별 의존, PENDING 상향 의무, 종료 범위·재개 조건, 경로 이력, 후보 기능/비교
의존을 읽는다. pending 외부 효과를 실제 확인한 후 reconcile한다. 완료 결과를
재사용하고 원본 실패를 덮어쓰지 않는다. 구버전은 보존 패키지로 복원하거나 명시적
migrate로 연결한 새 실행에서 재판정한다. 구버전의 답·완료를 새 충분성으로 승격하지 않는다.

## 매 판단: 계속할 의무와 끝낼 의무를 별도로 평가

observe의 run revision/state_digest, goal, information_needs, learning_frontier,
propagation_obligations, stale_refs, pending_operations, last_result와 실제 자원을
읽는다. DDC.observable_state는 그 revision/digest와 실제 확인한 facts다. 작업 설명을
관측으로 쓰거나 오래된 판단에 새 digest만 붙이지 않는다.

현재 변화가 건드린 범위에서 계속 조건과 종료 조건을 각각 평가한다. 같은 단위·범위에
동시에 성립하면 필요 능력·의존·근거·범위·버전을 다시 대조한다. 충분한 단위는 즉시
종료해 예약에서 빼고 상위로 반환한다. 독립 대안 질문은 별도 의무이며 현재 단위의
종료와 전체 목표 종료를 혼동하지 않는다. 동일 snapshot에서 종료 검사를 반복하지 않는다.

필수 선행·반박·적용·검증 공백은 실제 행동으로 연결한다. 의무의 존재와 행동 우선순위는
구분한다. 후순위로 둔다면 선택 대안·이유·영향·재포함 조건을 보존한다. 등록은 수행이
아니다. 바뀐 선행 상태를 관측하면 관련 의무를 다시 포함한다. 최종 Review까지 방치하지 않는다.

기존 9개 연산을 feasibility, consistency, critical gaps, decision uncertainty,
discovery value, marginal cost, Commit readiness로 비교한다. 이는 경쟁 정책이며
고정 파이프라인이 아니다. 직접 판별 가능한 선행 질문은 심화하고, 중복·무판별·편향
경로는 다른 정보원·메커니즘·Frame으로 전환한다. 임의 점수·확률·예산과 고정 깊이·
검색 수·K·beam·정체 횟수를 만들지 않는다. 의미적으로 동등할 때만 안정 ID로 기록
순서를 정하며 이를 품질 우열이라고 설명하지 않는다.

## 학습을 실행해 다음 탐색 공간을 생성

LearningTask가 질문·답·판단의 단일 원본이다. Frame.information_requirements,
Capability.extensions.questions, KnowledgeAsset.understanding[].questions는 task의
정확한 참조다. origin_refs/goal_connections는 발견 경로와 부모→원문 연결이고,
dependency_refs의 역할 관계는 실제 증명·비교 의존이다. DISCOVERED_FROM 이력은
자동으로 증명이나 무효화 의존이 되지 않는다. 상태 축의 의미는 learning-contract §21.4다.

학습 전 intent.learning_task_refs와 learning_plan에 정확한 task_ref, parent_role,
gap, next_observation, sufficient_when, failure_alternative를 기록한다. DISCOVER와
DEEPEN은 등록된 현재 질문을 선택해 실행한다. SCOPING은 두 연산의 작업 성격이며
열 번째 연산이 아니다. 실제 관측 후 네 묶음을 작성한다.

- 현재 답: 실제 읽은 출처 위치, 주장별 근거, 조건·범위·반대 근거·공백.
- 이해 변화: 선택·원리·전제·입출력·호환·실패·적용·검증에서 새로 판단할 수 있는 것.
- 새 탐색 공간: 발견한 개념·방법·기술·도구·선행·대안·검증법·교차 가지·Frame.
- 상향 효과: 부모·후보·원래 목표의 유지/수정/무효화/관측 필요와 근거.

발견 항목별 stable ID와 실제 source_locator, content, observation_kind, novelty,
parent_connection, assessment, disposition, target_refs, rationale, reopen_condition을
작성한다. 구체적 부모 연결과 미확보 능력이 있으면 자식 task를 생성한다. 역할·중요도가
불명확하면 구분할 scoping 관측을 실제 수행한다. 이름을 발견한 것과 이해를 구분한다.
자식의 최종 목표 효용을 미리 증명할 필요는 없지만 근거 없는 연상을 전부 중요하게 만들지 않는다.

CREATE_TASK/PREREQUISITE/REUSE/UPDATE는 실제 대상 참조, EXCLUDE는 근거, DEFER는
영향·재포함 조건과 남은 의무를 갖는다. 자식에서도 같은 평가와 실제 관측을 반복한다.
단계 수는 정하지 않는다. 답을 얻는 동시에 새 공간을 평가하고 자식의 결과가 부모
판단을 실제로 바꾸거나 근거 있게 유지하게 한다. ACCOUNTED는 발견 처리 의무가
등록됐다는 뜻이며 자식 완료가 아니다. 빈 발견 목록은 실제 조사 범위와 평가 근거가
있을 때만 허용된다. 고정 빈 목록·고정 피드백·정답을 미리 적는 driver를 만들지 않는다.

필요 능력→질문·증거→K0–K4 순서로 평가한다. K 라벨, 읽은 페이지 수, 도구 호출
성공은 충분성 증명이 아니다. 현재 자산의 충분성과 새 중요한 질문의 해결은 별개다.
깊이와 K는 독립적이다. 현재 판정을 막는 실제 공백을 따라가며 모든 기반 지식으로 확장하지 않는다.

## 충분한 단위와 생산성 없는 경로를 실제로 끝내기

종료 검사는 현재 필요 능력과 관측된 근거·반박·발견·필수 의존에 한정한다. 세계의
모든 가능성이나 종료 검사를 위한 새로운 종료 검사를 요구하지 않는다.

- 충분하면 CLOSED/ANSWERED, IDLE로 저장하고 다음 예약에서 제외해 상위로 반환한다.
- 비적용은 해당 부모 연결이 성립하지 않는 근거·범위로 CLOSED/NOT_APPLICABLE이다.
- 재사용/대체는 목표·환경·버전·능력·범위의 호환성을 확인하고 모든 부모·goal·의존·
  재개 의무를 보존해 REUSED/MERGED로 기록한다. 부족한 차이만 학습한다.
- 경로의 중복·무판별·부적절한 출처·반박 전제·정당화할 관측 부재는 path_assessments의
  PATH_END로 기록한다. 질문은 OPEN이며 다른 경로를 평가한다. 고정 실패 횟수는 없다.
- 실제 제약은 OPEN/PAUSED, CONSTRAINT다. 확보한 것·미완료 관측·영향·재개 조건을
  남긴다. 자원 제약을 충분성·답변 완료로 바꾸지 않는다.
- 아직 못 끝내면 OPEN과 실제 다음 행동·공백·선행을 저장해 controller로 반환한다.

closure_assessment.basis는 learning-basis가 현재 내용으로 계산한 hash다. hash가
판단을 생성하지 않는다. 호스트가 현재 범위·이유·근거·남은 불확실성·종료 사유를 평가한다.
새 중요한 반박, 환경/버전/목적 변화, 부모의 근거 있는 새 요구, 근거 무효화, 직접 범위
변경일 때만 material reopen_event를 쓴다. 더 자세히 알 수 있다는 가능성·같은 의문의
바꿔쓰기·다른 개념 발견만으로 종료를 뒤집지 않는다. 독립 의무는 별도로 평가한다.

## 자식에서 원래 목표까지 상향 반영

코어가 선언된 소비자에 PENDING 의무를 만든다. 호스트는 새 의미적 소비자도 찾아
역할 관계를 추가한다. source change/target/role/affected scope마다 유지·수정·
무효화·관측 필요를 평가한다. MAINTAIN도 실제 조건·범위·근거가 필요하다.
REVISE/INVALIDATE는 실제 대상 새 revision에 연결하고 NEEDS_OBSERVATION은
PENDING으로 남겨 구체적 다음 관측을 보존한다. 자식→부모→후보/원문 목표까지 처리한다.

근거 있는 유지로 의미 변화가 없거나 소비자가 없거나 동일 change-target-scope를
이미 처리했거나 실제 제약이 있을 때 전파를 끝낸다. 참조 버전 정리만으로 무한 전파를
만들지 않는다. 새 변화가 예전 미완료 의무를 대체하면 남은 의무를 함께 인계한다.
순환 그래프는 가능하나 순환 근거만으로 질문·기능을 충족할 수 없다.

## intent → 실제 작업 → 원자적 apply → 재관측

기록 형식은 실행 중인 패키지의 schema --entity로 조회한다. 원본 객체 수정에는
HostIO.edit의 깊은 복사를 사용하고, 같은 변경 묶음의 결과 참조는 patch-refs로
예상 버전을 조회한 뒤 명시적으로 연결한다. 형식이나 참조 오류가 나면 해당 ID·
예상 버전·허용 형식과 실제 입력을 대조한다. 이전 판단에 최신 버전만 덮어쓰지 않는다.
Review 입력은 review-context의 현재 투영을 사용한다. 미선택 자산 필터와 canonical
질문 투영을 별도 재구현하지 않는다. 질문별 평가와 탐색 충분성은 계속 호스트 책임이다.
structure의 기능·입출력 오류도 Gate와 같은 검사에서 조회하여 실제 연결을 수정한다.
반환된 참조는 HostIO.result_ref로 취하고 gate에 정확히 전달한다. 숫자를 추측하거나
오래된 Review를 새 후보에 자동 이전하지 않는다. 완료 작성은 schema --for-command
transition과 HostIO.complete의 명시적 성공 기준 검증을 쓴다. 형식 거부의 위치·필수 키·
타입을 실제 입력과 대조하며 필드명 추측 재시도로 판단의 공백을 덮지 않는다.
새 결과 구조나 오류 교정은 필요할 때 preflight로 원자적 적용 전에 검사한다.
이 검사는 모든 상태 변경을 되돌리며 실제 적용은 별도다. 닫힌 질문의 기록을 고치려고
학습 대상으로 다시 예약하지 않는다. 현재 유효한 결과는 재사용하고, 실제 의미 변경이
있을 때만 기존 재개 계약에 따라 재평가한다. 관측 연결 오류는 보존된 raw receipt와
EvidenceRecord.source 및 현재 learning_results의 실제 결과 참조를 각각 대조한다.
관측이 없으면 실제로 확보하며, 등록·hash 생성만으로 학습이나 의미적 지지를 만들지 않는다.

실행 전 intent를 저장한다. 실제 관측은 파일 등으로 먼저 보존할 수 있다. 중단으로
의미 평가가 끝나지 않았다면 pending으로 복원하며 성공 판단을 대신 작성하지 않는다.
실제 결과의 task·발견 처분·후속 참조·역할 의존·상향 의무·종료·DDC 피드백은 prepare
출력을 검토한 후 apply로 한 트랜잭션에 저장한다. prepare는 현재 필요와 의무를
전달하는 serializer이며 답·중요도·Review를 만들지 않는다. stale 결과는 실제 현재
상태와 재대조한다. 외부 멱등성과 로컬 중복 적용 방지를 혼동하지 않는다.

Review는 원문과 성공 기준 자체를 다시 검사한다. 초기 기준이 좁거나 현재 방법
밖의 유용한 탐색이 누락됐는지 재도출한다. 기능 증명(선택 경로·필수 전제·AND/OR·
입출력·조건·충돌)과 선택 비교 의존을 구분한다. 미선택 OR 변경은 선택 기능 증명을
자동 무효화하지 않으며 그 대안을 실제 사용한 비교 판단은 갱신한다. 같은 문서를
여러 검사에 연결했다는 사실로 모두 뒷받침된 것으로 보지 않는다. 개별 주장·조건의
실제 내용·범위를 확인한다.

정확한 snapshot에 원문 facet, 기능 조건, task별 답·능력·반박·범위, 중요한 열린/보류
의무, 미처리 발견, PENDING 상향 반영, 기능·선택 유효성, 추가 탐색 가치·실제 자원을
대조해 READY/NEEDS_WORK/PARTIAL_ONLY/BLOCKED를 기록한다. NEEDS_WORK는 실제
후속 작업을 등록하고 controller로 복귀한다. 미사용 자산의 모든 질문을 필수로 만들지
않지만 선택·원문 목표에 중요한 의무를 생략하지 않는다.

Commit은 exact gate 후 채택이다. 구현 요청은 그 후 실제 EXECUTE와 관측된 성공
기준 확인이 필요하다. 실패·새 중요 공백은 controller로 반환한다. 현재 호스트가
계속할 수 없으면 실제 중단 상태·영향·다음 관측을 저장한다. 문구·필드·구조 검사·
실제 판단·후속 행동·사용자 목표 달성은 서로 다른 증거로 보고한다.

### 관측 뒤와 반환 전의 실제 상태 연결 (§§5.3·13.4·21.7·26.2–26.4·27.6.12·27.9.8)

현재 문맥에 실제로 온전히 남은 구간만 retained 선언과 정확한 hash 영수증으로 다시
전달하지 않을 수 있다. 문맥 소실·잘림 뒤 영수증만으로 전문 확보를 생략하지 않는다.

관측 후 work-context --operation에서 선택 질문·답 상태·계획·현재 소비자·자산·후보와

문서에 새 질문을 강제하지 않으며 읽은 이름을 조합 평가로 치환하지 않는다.

HostIO.build_result는 호스트가 명시한 changes/result_ids/preserved_refs/evidence_refs/

실제 적용 후 work-context에서 답·발견·다음 작업·소비자·후보·상향 의무의 변경을 확인한다.

반환 전 work-context를 원문 목표와 대조한다. 방법 조사에는 필요한 조사·조합 검토를

않는다. 사용 가능한 필요한 작업은 계속하며, 실제 권한·자원·접근·중단 제약이면 근거와
영향·미반영·재개 조건을 보존한다. PARTIAL 표기는 미완료 의무의 소멸이 아니다.

공통/조건별 결과 범위를 보존한다. 사용자에게 추가 지식·기술 결정을 요구하지 않는다.

## §27.6 상세 조건의 실행 연결 — 2026-10-13

이 절은 필수 learning-contract.md §27.6 전체를 대체하지 않는다. 해당 원문의
22개 조건을 기존 객체와 실제 호출로 연결한다. 아래 사건이 발생한 범위에 적용하며
모든 사건·모듈을 매 회 실행하는 파이프라인으로 사용하지 않는다.

### 판단 전에 확보할 구별 단위 (§27.6.2–6)

중요한 조건의 발동/입력/기준/의무/금지 대체/반영/종료·보류/증거는 기존 DDC,
LearningTask, 연산, 관계, 해당 계약의 정확한 절을 사용해 연결한다. 참조 재사용은
현재 목적·환경·버전에서 유효한지 대조한다. 비적용은 이유이며 미확인은 비적용이 아니다.

GoalSpec facet의 interpretation에서 결과·필수 수단·제안 수단·제약을 구분하고,
inferred_requirements와 섞지 않는다. 원문→성공 기준의 누락 검사와 성공 기준→
원하는 실제 결과의 충분성 검사를 모두 수행해 preservation_rationale에 남긴다.
기준 변경은 해석 오류 교정/추론 요구 정교화/실제 사용자 변경 중 무엇인지 기록한다.
범위 제한으로 남은 원문 요구는 미충족 상태에 연결한다.

LearningTask.answer_requirements에서 안정 ID별 능력/판별 조건/충족 기준/근거 요구를
관측 전에 정의한다. parent role과 scope는 task.context 및 goal_connections를 참조한다.
학습 계획의 실패 대안은 해당 능력을 얻지 못할 때 남는 공백과 연결한다. 능력 기준을
수정하면 extensions.requirements_change.rationale/evidence_refs로 관측한 변경 이유를
남긴다. 현재 후보를 통과시키려고 기준을 낮추지 않는다.

intent.learning_plan의 각 항목에는 다음을 호스트가 실제로 작성한다.

- task_ref: 학습 대상의 정확한 현재 버전.
- requirement_ids: 이 작업이 구별할 answer_requirements의 안정 ID 목록.
- judgment_target: target_ref, item_id(객체 전체면 null), decision, consumer_refs,
  scope. 실제로 선택·수정·기각·유지할 판단과 그 사용처다.
- parent_role/gap: 현재 아는 것과 아직 모르는 차이가 어떤 판단을 막는가.
- known_evidence_refs: 실제 확보한 근거. 미확보는 빈 목록일 수 있다.
- next_observation: target/source/locator/information/decision_effect. 구별할 대상,
  실제 정보원·수단, 읽을 위치 또는 입력·조건, 얻을 정보, 달라질 판단을 명시한다.
- sufficient_when/failure_alternative: 현재 필요 능력의 충족 기준과 관측 실패 시
  남는 공백·다른 경로. 성공 결론을 미리 쓰지 않는다.

'더 조사한다'만으로 next_observation을 채우지 않는다. 단순 사실은 확인 위치와
사실 조건으로 충분하며, 없는 대안을 만들어 비교할 필요는 없다. 판단 대상·항목·
소비자 참조와 능력 ID는 코어가 확인하지만 관측의 판별력은 호스트가 평가한다.

### 관측에서 다음 학습으로 (§27.6.5·7–13·19–20)

현재 결론을 지탱하는 중요한 개념은 의미/작동 원리/전제/적용/경계/실패/확인 방법
중 현재 능력에 필요한 부분을 대조한다. 부족하면 어떤 설명이나 적용 판단을 막는지
찾아 후속 질문을 수행한다. 설명 안의 또 다른 중요한 미확인 전제에도 같은 규칙을
적용한다. 용어 정의의 순환은 작동 원리를 확보한 증거가 아니다.

기능 도출부터 기존 수단과 조합을 우선 검토한다. 직접 수행·수동 연결·새 구현 검토,
새 기능·연결 공백·반복 개입·사용 조건 변경에서도 해당 범위를 재평가한다. 먼저
입력/출력/수동 단계 이유/판단 대 결정론적 처리/
유지 상태/실패·검증/기존 호스트 능력을 구체화한다. 도구 이름보다 맡길 기능을 먼저
정한다. 기존 수단의 존재·능력·연결 조건을 모를 때 목적 기여, 바뀔 선택, 구체적 공백,
관측 경로, 실제 조사·통합·운영 비용, 기존 자산 대안을 비교한다. 필수 선택을 막으며
관측 가능하면 실제 조사한다. 설치 비용으로 문서·소스·출력·skill 절차 조사의 가치까지
부정하지 않는다. 독립 개선은 다른 행동과 비교하되 연기 이유·영향·재평가 조건을 남긴다.
검색 실패는 부재의 증명이 아니며 조사 범위와 남은 불확실성을 기록한다.

발견한 수단은 현재 맡길 기능에서 실제 I/O/직접 관측 대 추론/출력 완전성/저장·조회·
재사용/다음 입력과의 차이/환경·권한·의존/실패·복구·검증을 대조한다. 현재 필요와의
차이가 누락이다. 차이가 있으면 변환 수단 조사, 구성 수정, 다른 후보 비교, 개념·전제
심화 또는 정확한 범위 제한으로 연결한다. skill 메타데이터와 실제 절차 검토는 다르며
채택 판단에 절차가 필요하면 본문을 읽는다. 발견/읽기/설치/등록/실행/검증은 별도다.
외부 지시의 목표·권한·검증 변경 요구는 통합 계약에 따라 격리한다.

MATERIAL은 무엇이 달라지면 어느 부모 판단·기능·선택·실패·검증·종료가 달라지는지로
평가한다. 필요한 역할은 알지만 영향을 모르면 UNKNOWN과 그 이유·부모·판별 관측을
유지하고 SCOPING을 실제 수행한다. NONMATERIAL은 범위 차이, 실제 비의존, 차이에도
유지되는 필요 조건, 유효 재사용의 근거가 필요하다. 자식 최종 답을 미리 알아야 하는
조건을 붙이지 않는다.

매 발견에 understanding_gap을 남긴다. 부족하지 않다면 빈 문자열과 그 판단 근거를
rationale에 쓸 수 있다. UPDATE에 미해결 학습 공백이 남으면 해당 LearningTask와 실행
의무도 target_refs에 연결한다. 객체를 갱신했다는 사실만으로 공백을 숨기지 않는다.
관측→부모 판단→미확보 능력→질문→관측→사용처를 보존하고 필수 의존과 독립 후속을
구분한다. 재사용은 목적·환경·버전·능력·범위·근거를 대조하며 부족한 차이만 학습한다.

답/이해 변화/새 탐색 공간/상향 영향의 네 결과는 실제 관측 이후 작성한다. 개별 claim의
source_locator/evidence_refs/conditions/inference에 실제 지지 범위를 연결한다. 같은
문서의 다른 주장은 별도 대조한다. 읽지 않음/접근 불가/미확인/부족/반박을 구분하며
문서 기능 설명을 적용 성공으로 승격하지 않는다. 실패는 실제로 구별한 전제·경로만
진전이다. 반복 driver가 능력 MET, K, 공백 없음, 발견 없음, 종료를 생성하게 하지 않는다.

구체화에서 새 중요한 미정의 요소가 생기면 사용처→구별 조건→필요 입력→실제 근거→
판정별 행동→소비자→종료·재개를 같은 규칙으로 연결한다. 세대 제한 없이 적용하되
실제 출처의 사실, 정의된 상태·관계, 구체적 행동, 범위 있는 의미 평가 또는 유효한 기존
지식에 도달하면 멈춘다. 현재 판단을 바꾸지 않는 언어적 분해나 메타 검사를 늘리지 않는다.

### 실행 의무·반영·종료가 다음 선택을 바꾸게 하기 (§27.6.11·14–19)

매 상태 변화에서 영향을 받은 필수 전제/반박/적용·검증 공백/UNKNOWN/상향 PENDING을
관측해 다음 가능한 행동에 포함한다. 더 싼 행동이 있다는 이유로 의무를 삭제하지
않는다. DEFERRED에는 closure_assessment.selected_action/comparison_rationale과 기존
impact/remaining_work/reopen_conditions를 저장한다. 선행 해소·근거 변화 시 다시 비교한다.

자식 결과의 의미 변화는 source change/target version/role/scope별 반영 의무로 평가한다.
MAINTAIN은 실제 현재 target_ref를 result_refs에 넣고 조건·범위 대조를 기록한다.
REVISE/INVALIDATE는 실제 새 대상 버전, NEEDS_OBSERVATION은 필요한 관측과 PENDING이다.
선언되지 않은 의미적 소비자는 호스트가 찾아 보완한다. 필요한 기능·후보·선택 이유·
성공 기준·원문까지 반영한다. 안정된 유지/소비자 없음/같은 변화 처리/실제 제약에서
전파를 끝내며 미완료 의무는 남긴다. 질문 종료와 상향 완료는 별개다.

충분 종료의 여덟 조건(원문·부모에서 도출한 능력, 실제 근거, 조건·한계, 선행,
반박, 발견, 잔여 불확실성, 현재 버전)을 대조한다. 모두 성립하면 CLOSED/ANSWERED,
IDLE로 끝내고 예약에서 빼며 결과를 반환한다. 독립 질문을 모두 현재 필수 조건으로
편입하지 않는다. 경로 무판별이면 PATH_END와 남은 OPEN 질문/대체 경로, 실제 제약이면
PAUSED와 답·미완료 관측·영향·대안·재개를 보존한다. 계속과 종료가 같은 단위에서
충돌하면 능력/의존 역할/범위/버전/UNKNOWN 치환 여부를 재대조한다.

재개는 중요한 반박·조건·환경·버전·목적·근거·부모 필요 능력 변경이 종료 범위를
건드릴 때만 한다. 변경 사실과 이전 근거의 차이, 영향받는 능력·주장, 다음 관측을
reopen_event.rationale과 현재 학습 계획에 연결한다. 독립 새 질문은 별도 의무다.

Review는 원문과 기준 자체, 기능 증명, I/O·전제, 주장 범위, 필요한 이해, UNKNOWN·보류,
상향 PENDING, 기능/선택 유효성, 추가 행동 가치와 실제 결과 범위를 현재 버전으로
대조한다. 이미 선택한 방법의 구현만을 추가 행동 대안으로 두지 않는다. 관측에 근거한
개념/전제/기존 방법·skill/연결/다른 메커니즘 조사도 판단을 바꿀 수 있는지 평가한다.
세계의 모든 대안을 요구하지 않는다.

선택·미선택 자산의 독립 질문도 원문·선택 영향을 평가한다. 보유 여부나 선택 여부가 필수 공백과 독립 개선을 대신 분류하지 않는다. Review.extensions의
independent_followups에서 해당 미완료 task마다 task_ref/status(CONTINUE/DEFER/
NO_CURRENT_EFFECT)/decision_impact/rationale/evidence_refs/requeue_condition을 작성한다.
CONTINUE는 READY를 막는다. DEFER나 NO_CURRENT_EFFECT는 현 결론에 대한 범위 있는
근거를 요구하며 해당 질문을 해결했다고 의미하지 않는다. 미사용 질문 전부의 해결을
요구하지도 않고 독립이라는 이름으로 전체 Review에서 지우지도 않는다.
NEEDS_WORK에는 실제 OPEN/DEFERRED LearningTask, 미완료 OperationRecord 또는 이번에
실제 갱신한 DependencyLink의 followup_refs를 연결하고 컨트롤러로 돌아가 작업한다.
결함이 의존 수정으로 해결된다면 불필요한 학습 질문을 강제로 추가하지 않는다.
READY만 gate로 간다. PARTIAL_ONLY는 원문 미충족 범위를 보존하고,
BLOCKED는 실제 장애·대안·재개를 기록한다. COMMIT과 요청한 실행 결과는 별개다.

실제 관측 파일을 먼저 저장하고 필요하면 observe-result로 pending intent에 path/hash/
source를 연결한다. 의미 평가 전 중단되어도 원본 관측과 미평가 상태가 복원된다.
이 명령은 기존 연산의 기록 관리이며 새 추론 연산이 아니다. 이후 prepare/apply로
평가·의무·피드백을 원자적으로 반영하고 새 상태를 읽는다. 복원은 계약·코드 identity,
미평가 관측, 선행/보류/상향, 종료 범위와 외부 실제 효과를 확인한다. 옛 답·K·Review를
새 승인으로 승격하지 않는다. 지침/상태/구조/판단/행동/목표의 증거 수준을 구분한다.

## §27.7 자동화 우선 계약의 실행 연결

필수 learning-contract.md §27.7의 24개 조항 전체가 기준이다. 이 절은 기존 저장
표현·호출의 연결이며 원문을 대체하지 않는다. 사건이 발생한 범위에 적용하고 모든
자산 범주·모듈을 매번 순서대로 수행하지 않는다.

### 기능 도출에서 발동 (§27.7.1–7)

원문 facet/interpretation과 explicit_constraints에서 명시적 수동 요구와 그 단계를
확인한다. 방법 안내 요청은 수동 선호가 아니다. 호스트의 직접 처리와 사용자 수동
수행을 구분하고 없는 선호·권한을 만들지 않는다. 기존 양방향 목표 보존을 적용한다.

DERIVE_CAPABILITY에서 방법을 정하기 전에 필요한 결과를 정의한다. inputs/outputs/
satisfaction_conditions/derivation_refs에 현재 충족·연결 판단에 필요한 출처·소비자·
주체·판단/처리·시점·반복·상태·실패 관측을 연결한다. 저장·조회·적용·검증 안의 중요한
미정의 요소도 같은 구체화 규칙으로 판별한다. criterion_ids는 답변 목차가 아니다.

이 기능을 제공하는 현재 호스트·프로젝트·설치 skill·관련 외부 수단과 조합의 활용
가능성을 평가한다. 도구 선택·사용·조합 판단이 필요한 목표에서는 기존 능력의
충분성과 관계없이 현재 후보 밖을 실제 탐색하고 기존·신규 후보를 함께 검토한다
(§§27.8–27.10). 기존 능력 평가의 종료는 별도 탐색 의무의 종료가 아니다. 이미
실제 수행한 동일 범위의 유효 관측은 재사용하며, 중요 공백이 범위 밖이면 차이를 조사한다.
작은 작업·익숙함·설치 여부만으로 비적용을 선언하거나 후보를 제외하지 않는다.

중요한 존재·능력·조건이 미확인이고 판별 경로가 있으면 LearningTask의 question/
answer_requirements/context/assessment/goal_connections에 등록한다. Capability의
extensions.questions에 정확한 task 참조를 연결하고 prepare/apply 후 새 observe의
information_needs/frontier에서 실제 DISCOVER/DEEPEN과 learning_plan을 선택한다.
등록·미확인 표시는 수행이 아니다. 조사 비용과 설치 비용을 구별한다.

직접 수행·새 구현·수동 보완 검토, 새로운 기능·연결 공백·반복 개입·조건 변경에서도
같은 평가를 해당 범위에 적용한다. 유효 평가 재사용은 다시 조사하는 것과 다르다.
검색 실패는 조사 범위와 남은 공백이며 부재의 증명이 아니다.

### 발견·심화·연결에서 재귀 수행 (§27.7.8–11·14)

관련 skill은 설명에서 멈추지 않고 선택에 필요한 실제 SKILL.md·참조·보조 자원의
절차를 읽는다. KnowledgeAsset의 applicability/availability/I/O/contextual task와
EvidenceRecord에 실제 기능·주체·조건을 연결한다. 이름 확인/절차 검토/적용 조건/
연결 판단/실제 적용/검증은 claim.conditions/source_locator와 observed_effects에서
구분한다. 읽기를 실행 성공으로 승격하지 않는다.

선택·연결·실패 대응·검증에 필요한 원리·전제·출력·누락·저장/조회·주체의 능력을
먼저 정의하고 실제 근거로 구별한 뒤 K를 요약한다. 모든 내부 원리 학습은 요구하지 않는다.
개별 유용성만으로 연결을 인정하지 않는다. candidate.connections와 DependencyLink에
실제 출력→입력·선행·변환·조건·정확한 근거 버전을 연결한다. 타입 일치는 의미·단위·
식별·완전성·범위·환경·순서·상태·전달 주체·복구의 증명이 아니므로 필요한 부분을
task와 근거로 판별한다. '자동 사용'은 발동 사건/찾아 읽는 주체/선택 자료·버전/
구현 판단 적용/부재·오래됨·충돌 처리/실제 사용 관측으로 다시 구체화한다.

공백은 능력 미확인·설정·형식·정보 누락·절차 단절·환경·관측된 기능 부족·원리 이해
중 실제 차이를 판별한다. 즉시 새 연결 코드나 skill을 만드는 대신 설정·기존 변환·
정보원·호스트/skill 절차·다른 조합·개념 심화의 판별력과 비용을 비교해 선택한다.
모든 경로를 실행하는 목록이 아니다. 발견한 연결 수단에도 같은 심화·연결 계약을
적용한다. 그 결과의 중요한 공백도 expansion의 실제 관측→부모 판단→understanding_gap
→후속 task→관측→사용처로 연결해 실제 수행한다. 자식의 자식에도 세대 제한이 없다.

### 후보·새 구현·수동 보완과 작업 의무 변경 (§27.7.12–17)

필수 기능·품질·환경·권한·연결·검증·복구를 먼저 대조한다. 충족 후보들 사이에서
사용자 개입, 호스트 수행 범위, 기존 능력 재사용, 새 기능·연결, 확인 가능한 조사·
통합·운영 부담과 실패 대응 차이를 attributes/comparison_rationale에 기록한다.
실제 비교 근거는 COMPARES_USING/judgment_dependencies에 연결한다. 없는 대안·점수를
만들지 않는다. 필요한 조건을 만족하면서 사용자 개입을 줄이는 기존 조합을 우선한다.

새 구현은 기존 제공/설정/조합/미확인/실제 추가 구현 필요를 구별한 뒤 남는 구체적
공백에만 선택한다. DDC·intent에 공백·재사용 범위·추가 I/O/전제·연결 위치·대안·
선택 근거·검증·복구를 연결한다. 미확인은 부재가 아니다. 알려진 유효한 변환은
재사용하고 세계의 모든 도구가 부적합하다는 증명을 요구하지 않는다.

수동 우선은 원문에 명시된 범위다. 그 외 수동 보완은 자동화 평가 뒤 남은 기능·
실제 한계·미확인·권한, 호스트 대행 가능 부분, 사용자만 할 부분, 일회 설정/반복
개입, 재자동화 조건을 DDC·정확한 결과 범위에 남긴다. 호스트가 할 기술 작업을
사용자에게 넘기지 않는다. 권한 부족은 대체 경로와 미충족 상태로 보존한다.

새 수단이 직접 작업이나 사용자 작업을 대체하면 후보 소개만 추가하지 않는다.
실행 의무도 재평가한다. LearningTask를 변경 범위의 근거로 수정하거나 기존
NOT_APPLICABLE/유효 재사용 등으로 끝낸다. 미완료 외부 OperationRecord는 실제
효과 확인 후 기존 reconcile로 정리한다. 새 후보 revision과 의존·검증을 갱신하고
남은 작업은 실제 frontier/후속 intent에 보존한다. 폐기한 예전 작업을 계속 예약하지 않는다.
상향 PENDING은 실제 REVISE/INVALIDATE/근거 있는 MAINTAIN으로 해소하거나 필요한
관측으로 유지한다. 부모·기능·후보·원문까지 영향을 처리한다.

단일 MC의 기존 feasibility/consistency/critical gaps/decision uncertainty/discovery
value/marginal cost/Commit readiness를 유지한다. 자동화 평가가 권한·일관성·중요
실패 처리를 밀어내지 않고 싼 직접 작업도 중요한 평가 의무를 삭제하지 못한다.
Reframe은 기존 네 트리거다. 새 컨트롤러·연산·고정 단계 수를 만들지 않는다.

### 종료·검토·복구·증거 (§27.7.18–24)

기능과 선택·연결·실패·검증 능력·조건, 필수 전제·반박·발견 처리와 범위가 충분하면
현재 질문을 종료해 예약에서 뺀다. 더 많은 도구가 가능하다는 막연한 이유로 계속하지
않는다. PATH_END와 OPEN 질문, 실제 제약/연기와 충분 종료를 구분하고 남은 영향·
대안·재선택 조건을 보존한다. 중요한 독립 대안과 현재 단위의 종료는 별도다.

Review는 기능별 기존 능력 평가·필요 절차 독해, 개별 능력 대 연결, 실제 새 구현
공백, 사용자 개입 필요, 상향 결과의 후보·작업 반영, 중요 미사용 대안·추가 탐색을
현재 스냅샷에 대조한다. 기존 capability_conditions와 checks의 coverage/io/knowledge/
evidence/complexity/selection/marginal_value에 해당 판단과 근거를 연결한다. 별도로
구별할 중요한 조건은 기존 checks 사전에 안정적인 키로 추가할 수 있다. 선언된
모든 검사의 FAIL/UNKNOWN/유효 근거 부재는 Gate를 막는다. 추가 JSON 필드나
특정 자동화 검사 이름을 필수로 만들지 않는다. PASS의 진실은 호스트 책임이다.

평가 누락·중요 연결 미확인·필요 skill 절차 미독해·주체 없는 자동 실행 주장·
상향 미반영·근거 없는 새 구현/수동 보완은 NEEDS_WORK의 실제 task/operation/의존
갱신으로 연결하고 해당 작업을 선택한다. 범위 제한은 원문 미충족도 보존한다.
READY/Gate·채택과 요청된 실제 구현 완료를 구분한다.

기존 observe-result/prepare/apply/checkpoint/restore로 실제 관측·미평가 결과·남은
조사·연결·상향 의무·종료 범위를 복원한다. 구버전 승인은 자동 승격하지 않는다.
실제 자산 능력·연결·사용 가능성·명시적 수동 요구 변화가 다른 선택과 행동을 만드는지
관측한다. 성공 판단을 생성하는 fixture, 실제 작성 호스트, 독립 평가의 증거를 구분한다.


## §§27.8–27.10 신규 탐색·통합 조합·누락 차단의 실행 연결

필수 learning-contract의 55개 항목 전체를 함께 적용한다. 이 절은 실행 연결이며
원문 대신 읽는 요약이 아니다. 보유 도구에 익숙함과 새 도구의 낯섦으로 기능·후보·
탐색 범위를 결정하지 않는다. 적용 대상의 실제 신규 탐색은 현재 후보의 부족함이나
새 후보의 예상 효용을 먼저 입증해야 발동하는 선택적 개선이 아니다.

### 목표에서 책임을 찾고 실제 다음 행동으로 연결

solve는 `<goal-id>:tool-scope` LearningTask를 UNANSWERED/UNASSESSED/OPEN으로
등록한다. 실제 적용 판단은 호스트가 원문 facet·필요 기능과 대조한다. 초기 문구는
기계적인 미평가 질문이며 실제 관측이나 이해·중요성·비적용 답이 아니다. 질문의
context/answer_requirements를 현재 판단에 맞게 구체화하고 변경 근거를 보존한다.

도구 선택·사용·조합이 필요하면 적용 판정을 근거 있는 CLOSED/ANSWERED로 저장한다.
코어는 두 책임을 기존 LearningTask로 미해결 등록하고 prepare/apply 후 실제
information_needs/frontier/next_decision_inputs에 전달한다. 등록은 수행이 아니다.
새 observe에서 두 의무가 각각 나타나는지 확인하고 가능한 실제 DISCOVER/DEEPEN/
EXPAND 행동에 포함한다. 더 우선하는 행동을 선택해도 미수행 의무·영향·재선택
조건을 남기며 완료 직전까지 영구 연기하지 않는다.

도구 판단이 필요하지 않으면 원문·기능에 대한 실제 근거로 NOT_APPLICABLE을
판정한다. 작은 작업·방법 안내·기존 도구의 충분성은 비적용 근거가 아니다.
SUPPORTED 답·필요 능력·관측 범위·ACCOUNTED 평가와 현재 closure basis를 유지한다.
이 경우 두 의무를 불필요하게 수행하지 않는다. 중요 기능·Frame·범위·환경·목표
변경에서는 적용 범위와 기존 평가를 재대조하며 옛 승인을 새 버전으로 복사하지 않는다.

### 현재 후보 밖을 실제 탐색하고 범위를 판별

신규 탐색은 `<goal-id>:tool-discovery`에 연결한다. goal_link/actual_search/
observed_scope/selection_effect/termination의 다섯 요구를 현재 목표에 구체화한다.
식별자의 고정은 책임의 연결이며 검색 횟수·문서 수·K·깊이를 고정하는 것이 아니다.

learning_plan에는 기능→방법 질문→기존 접근의 전제→조사 경로·실제 입력→구별할
정보→판단 영향→실패 시 남는 공백을 연결한다. 기존 이름·설정·확장만 검색하고
더 넓은 메커니즘을 조사했다고 주장하지 않는다. 목표의 기능을 다른 원리로 수행할
가능성을 드러낼 수 있는 질문·자료를 사용한다. 새 후보의 발견 자체는 강제하지 않는다.

intent를 저장한 뒤 실제 자료·도구를 사용한다. 결과 파일을 보존하고 observe-result로
pending 연산에 path/hash/source를 연결한다. actual_search 능력의 EvidenceRecord.source는
실제 원본 출처 또는 해당 관측 파일의 절대 경로에 연결한다. claim.source_locator에는
읽은 위치·입력·범위를 구체화한다. 코어는 파일·연산·근거 연결을 확인하며 내용의
관련성·진실·탐색 충분성은 호스트가 평가한다. 무관한 실제 파일도 의미적으로 실패다.

관측 이후 현재 답/이해 변화/새 탐색 공간/상향 영향을 실제 내용으로 평가한다.
검색 성공과 질문 해소를 구분한다. 실패·무판별·중복·접근 불가는 해당 경로와
범위에 한정하고, 중요한 질문이 남으면 다른 질문·자료·경로·심화로 연결한다.
빈 발견 목록은 실제 조사 범위와 평가로 설명한다. 결과와 관계없는 빈 공백·K·
성공·종료·다음 판단 입력을 만들지 않는다.

실제 관측이 무엇을 구별했고 무엇을 구별하지 못했는지, 남은 차이가 현재 선택을
어떻게 바꿀 수 있는지 대조한다. 필요한 구별이 끝나면 현재 탐색을 종료한다.
새 도구를 못 찾았다는 이유로 무한 탐색하거나, 현재 도구로 충분하다는 이유로
실제 신규 탐색을 생략하지 않는다. 불가능한 관측은 미완료 영향과 정확한 상태로 남긴다.

### 기존·신규 후보의 통합 검토와 재귀 후속

`<goal-id>:tool-composition`은 roles/dispositions/combinations/connections/
comparison/remaining_work를 구체화한다. 후보 편입 전후 모두 실제 역할·근거·
단독 및 보완 가능성·미확인·범위를 평가한다. 정보 부족을 낮은 성능으로 바꾸지
않으며 신규 탐색을 이유로 보유 후보를 삭제하지 않는다. 사용자 교정은 해당 범위의
탐색·비교 수정이며 명시적 금지가 없다면 후보 일괄 삭제가 아니다.

기존끼리·신규끼리·혼합이라는 이름 대신 기능·출력→입력·전제·변환·주체·실패·
검증을 실제로 대조한다. 단독·대체·보완·혼합의 관련 가능성을 검토하고 미조사
영역은 역할·확인된 제약·중복·비교 근거로 설명한다. 모든 부분집합을 열거하거나
관련 가능성이 미확인인데 편의상 제외하지 않는다.

비교 기준은 목표 기능과 실제 다음 소비자의 입력에서 도출한다. 선택 중인 도구의
전용 형식과 다르다는 사실만으로 대안을 낮게 평가하지 않으며, 실제 필요한 변환·
정보 손실·도입 부담을 비교한다. 확인된 한계와 미검증을 구분하고, 관측 수준의 차이만
남았다면 확인한 범위의 선택 근거로 보고한다. 모든 후보에 동일한 실행 횟수를 강제하지 않는다.

새 중요한 공백은 부모 판단→미확보 능력→자식 질문→실제 관측→소비자로 연결한다.
자식·후손에서도 같은 규칙을 적용한다. 충분한 단위는 닫으며 이미 유효하게 조사한
동일 범위는 재사용한다. 새로운 공백이 그 범위 밖이면 차이를 조사한다. 모든 자식에
같은 외부 검색을 반복하는 규칙으로 바꾸지 않는다.

탐색과 조합 작업은 번갈아 수행할 수 있다. 최종 통합 조합의 closure에는 현재
discovery 결과를 COMPARES_USING으로 연결한다. 탐색이 바뀌면 후보의 기능 유효성과
선택 유효성을 구분하고 조합의 비교·남은 작업을 재평가한다. 중요한 반영 PENDING은
실제 대상 수정·근거 있는 유지·관측 필요로 처리한다. EXPAND_COMPOSITION의 현재
learning_results에는 실제 역할·연결·비교 관측과 대상별 상향 영향을 남긴다.

### 의무·공백·독립 개선별 차단과 종료

두 계약상 필수 의무는 보류해도 미충족이며 채택을 막는다. 이 책임을 INDEPENDENT나
NONMATERIAL로 낮출 수 없다. 현재 선택의 기능·연결·중요 실패·검증을 막는 질문은
해결하거나 실제 의존 제거·범위 제한을 해야 한다. 단지 링크 삭제로 해소하지 않는다.

현재 결론을 훼손하지 않는 독립 개선은 선택된 자산의 질문이어도 별도로 관리한다.
원문·선택 영향과 유지 조건의 근거, 보류 영향·재검토 조건을 평가한다. UNKNOWN이면
영향을 실제로 판별한다. Review의 independent_followups에서 CONTINUE는 후속 수행,
근거 있는 DEFER/NO_CURRENT_EFFECT는 미해결 상태 보존이며 현재 단위 종료를 허용한다.
해당 질문의 해결로 기록하지 않는다. 모든 미사용 대안이나 미래 활용을 필수화하지 않는다.

### Review·적용 후 재관측·복원

현재 목표→적용 판정→두 의무→실제 관측/역할/연결/비교→후속 발견/작업 반영→현재
Review를 조회한다. 필수 의무를 Review 검사 목록에서 빼도 안정적인 책임 조회와 Gate
차단은 유지된다. 실제 검색의 적절성·후보 배제·중요성·원문 보존은 호스트가 따로 평가한다.

NEEDS_WORK는 정확한 미완료 질문·연산·실제 의존 수정에 연결한 뒤 그 작업으로 돌아간다.
prepare/apply 뒤 새 observe에서 질문·공백·후속 경계·상향·후보/선택 버전·예약 제외를
확인한다. 저장 성공·문구 변경만으로 연결이 완료됐다고 하지 않는다.

중단 후 등록만 됨/intent만 있음/관측 후 미평가/평가 후 미적용/상향 미완료/유효 종료를
구분해 복원한다. 실제 효과 확인과 기존 reconcile 후 재시도하며 완료 관측을 재사용한다.
코어 검사·선언 fixture·작성 호스트의 실제 판단·독립 평가·목표 충족의 증거를 구분한다.

## §§27.11–27.12 목표 해석의 지지·누락 검토 실행 연결

필수 learning-contract의 두 계약 46개 항목 전체를 적용한다. 현재 성공 기준을
원문 자체로 취급하지 않는다. 최초 기준은 잠정 해석이며 공통 유효 작업의 시작은
가능하지만 진척·도구 실행·자기 기준의 충족을 해석 충분성으로 역산하지 않는다.

### 원문에서 기대 책임과 판단 입력을 확보 (§27.11.1–8·15–17, §27.12.1–6)

solve가 `<goal-id>:goal-interpretation`을 OPEN/UNANSWERED/UNASSESSED로 등록한다.
observe.goal_interpretation과 실제 LearningTask를 읽는다. 등록은 지지·누락 검토의
답이 아니다. 모든 목표에서 검토하되 복수 해석·Frame·외부 검색은 강제하지 않는다.

원문·기존 맥락·실제 사용 조건을 먼저 읽는다. 현재 기준·기능·후보도 읽되 그것만을
입력으로 삼지 않는다. 결과의 용도/범위/일회·재사용/보존·변환/규칙·상태·연결·검증/
요청 유형 중 선택을 바꿀 성질을 구별한다. 미확인 성질은 작업 목록으로 대신하지 않는다.
원문 명시·맥락·기술 추론·미확인을 구분하고 원문 자체, AI 해석, 해결 Frame을 분리한다.

현재 LearningTask의 일곱 능력은 원문 보존, 결과 성질, 중요 관점, 차이 영향,
관측 대 미확정, 실제 소비, 종료·재검토다. 능력 이름을 채우는 대신 현 목표에서
무엇을 구별해야 하는지 context/answer_requirements/learning_plan에 구체화한다.
기준 변경은 requirements_change의 실제 근거를 사용한다. 고정 K나 관점 수는 없다.

중요한 해석은 안정 ID로 기록한다. 원문 facet, 결과 범위, 가정과 근거 종류,
실질적 차이, 달라질 판단, 불확실성, 소비자, 처리 이유·재개 조건을 연결한다.
이름·문장·목록 순서를 바꿔 의무를 삭제하지 않는다. 중복은 원문·미완료 연결을 보존해
병합한다. 유명 도구나 큰 체계라는 이유만으로 새 요구를 만들지 않는다. 전문 용어를
몰라도 필요한 결과의 성질과 미확보 능력으로 조사 질문을 도출한다.

### 두 종류의 대조를 실제 수행 (§27.11.9–14, §27.12.4–10)

검토 작업을 선택할 때 fresh observe의 원문/현재 해석/공백/가능 행동/비용에 근거해
DDC를 작성하고 intent를 먼저 저장한다. Goal Compiler 또는 기존 아홉 연산에서
학습 대상 task와 계획을 연결한다. 코어는 연산·답을 선택하지 않는다.

**지지 경로:** 원문·맥락 → 현재 해석과 명시되지 않은 가정 → 필요 결과·기능 →
현재 후보·근거를 실제 대조한다. 현재 방법의 능력·사용법 확인은 이 범위의 증거다.

**누락 검토 경로:** 현재 기준을 잠시 분리하고 원문 결과·사용 조건에서 현재 해석의
범위를 대조한다. 원문→결과에서 빠진 성질과 결과→원문에서 임의 추가한 조건을
각각 검사한다. 현재 후보가 계획대로 성공해도 원문이 허용하는 중요한 사용 목적을
놓칠 조건이 있는지 구별한다. 반례는 원문·맥락·관측된 기능/조건에 연결한다.
실제 차이가 없다면 조사한 범위와 이유를 기록하며 가짜 반례를 만들지 않는다.

두 경로의 대상·읽은 위치·범위·근거·판정을 각각 기록한다. 같은 자료를 사용할 수는
있지만 같은 긍정 근거 묶음에 두 이름을 붙여 수행을 대신하지 않는다. 도구 수,
실행 가능성, 자기 기준/질문 완료, 무검색 결과, 미입증 효용, 사용자가 용어를 말하지
않음, 이미 들인 비용은 누락 검토의 대체가 아니다. 검색 미발견·중요 차이 미관측·
현재 해석 충분은 서로 다른 판정이다.

목표의 결과 성질에서 개념·방법·skill로 내려가고, 관측한 수단의 다른 결과 구조에서
원문으로 돌아온다. 자료/skill의 관련 표현은 후보 근거이며 의도 확정이 아니다.
중요 구조를 읽고도 무시하지 않고 전체 체계를 요구로 확대하지도 않는다. 필요한
부분과 선택 확장, 기능·작업·검증의 실제 차이와 후속 사용처를 평가한다.

현재 접근 확인/관점 누락 판별/후보 비교를 구분한다. 사용법과 유사 제품 조사만으로
결과 관점까지 검토했다고 하지 않는다. 기존·신규 수단은 공통 기준으로 평가한다.
적용되는 신규 도구 탐색·통합 조합은 별도 의무이며 해석 검토의 종료로 면제되지 않는다.

### 차이에서 후속 작업과 결과로 (§27.11.7·12–14·18–20, §27.12.8–13)

차이가 목표 충족·기능·역할·적용·권한·실패·작업·검증·추천 범위를 바꿀 구체적
연결이 있으면 중요성을 평가한다. UNKNOWN을 NONMATERIAL로 바꾸지 않는다.
차이 → 부모 판단 → 미확보 능력 → 가능한 관측이 있으면 실제 관련성/심화 작업을
선택한다. 더 좋은 해법이나 전문 용어의 사전 발견은 필요하지 않다.

차이는 canonical expansion.discoveries에 실제 위치/추론 구분/understanding_gap/
assessment/disposition/target_refs로 보존한다. 관련성 미확인은 SCOPING,
필수 전제는 실제 의존, 선택 질문은 선택 책임, 독립 개선은 근거 있는 별도 처리다.
CREATE_TASK는 수행이 아니며 자식·후손에도 계속·종료 계약을 적용한다. 새 관점은
정보 요구·기능·후보·작업·검증에 연결한다. Frame을 결과 설명의 이름표로 만들지 않는다.
실질적 차이가 있으면 기존 Initial/Discovery/Deficiency/Stagnation 조건과 단계로
생성·변경한다. 단순 문구 교정에 Reframe을 강제하거나 새 트리거를 만들지 않는다.

기술 사실은 조사로 판별하며 기술 문서로 개인 선호를 확인했다고 하지 않는다.
기존 원문·맥락으로 해석별 차이를 평가하고 추가 사용자 지식·설명을 요구하지 않는다.
확정할 수 없는 선호·권한은 남긴다. 공통/동등 범위면 근거 있게 병합·진행하고,
조건별로 처리 가능하면 결과·방법·역할·작업·검증을 실제 구성한다. 현재 자료로
판별 가능한 조건은 호스트가 판단한다. 사용자가 전문 체계를 공부해야 답을 사용할
수 있는 구조나 '원하면 더 한다'는 문장으로 처리를 대신하지 않는다. 조건부 답이
제거한 의존과 남은 범위를 보존하며 미확정 의도 자체를 해결했다고 쓰지 않는다.

변경은 해석 오류 교정/추론 정교화/실제 사용자 변경으로 구분한다. GOAL_COMPILE의
원문 보존 교정으로 기준을 바꾸면 현재 GoalSpec을 사용해 검토 책임·소비자·Review를
재평가한다. 무관한 지식과 관측은 유지한다. interpretation_review.effects와 기존
상향 의무에 실제 대상·범위·MAINTAIN/REVISE/INVALIDATE/NEEDS_OBSERVATION을 연결한다.
유지는 현재 조건·근거의 대조 결과이며 사전 고정 문구가 아니다. 수정은 실제 새
대상 버전이며 관측 필요는 남은 작업이다. 필요한 의무를 순위가 낮다는 이유로 삭제하지 않는다.

관측을 먼저 파일로 보존하고 observe-result로 intent에 연결한다. 실제 대조 이후
답/이해 변화/새 탐색 공간/상향 효과를 작성해 prepare/apply한다. 두 경로 근거는
실제 보존 파일/원출처와 연결한다. 다른 위치의 같은 원자료 재사용은 가능하다.
파일·해시·기록은 의미적 적절성을 증명하지 않는다. 적용 후 observe에서 실제
후속 frontier, 소비자 revision, 기준·후보·작업 변화, 새 공백, 종료 예약 제외를
확인한다. 연결이 빠졌으면 수정하며 문구 변경만으로 완료하지 않는다.

### 충분성·Review·복원 (§27.11.21–27, §27.12.11–19)

판정 내용은 현재 해석 진행 충분 / 복수 해석 처리 충분 / 중요 차이 미처리다.
새 실행 상태 enum이 아니다. 현재 검토에서 지지·원문 양방향 대조·성공해도 놓칠
조건·관측된 구조·중요 차이 처리·잔여 불확실성 영향·소비자 반영·현재 버전·재개
조건을 확보하면 이 단위를 끝낸다. 유일한 숨은 의도를 알아내는 것이 종료 조건은 아니다.

계속은 실제 차이/사각지대 → 달라질 현재 판단 → 미확보 능력 → 가능한 관측이
있을 때다. 표현 중복, 근거 없는 확장, 이미 처리한 차이, 영향 없음이 확인된 차이,
관측이 현재 해석을 지지한 경우는 끝낸다. 막연한 누락 가능성으로 무한 검토하지 않는다.
접근·실행 제약의 중단은 충분 종료가 아니며 공백·영향·재개와 부분 결과를 보존한다.

Review는 선언된 검사명/Frame 목록과 별도로 현재 목표에서 기대 책임을 조회한다.
지지 경로와 누락 검토 경로 각각의 실제 대조/근거/처리/소비/종료를 재확인한다.
미판별 중요 차이, 등록만 된 후속, 미반영 결과, 오래된 목표·소비자, 형식적인 조건부
문장, 임의 확대·축소는 NEEDS_WORK와 실제 followup_refs로 돌려보낸다. 정확한 복수
처리는 허용하고 임의 단일 해석을 강제하지 않는다. READY 저장/Commit에는 코어의
기대 책임·두 경로·현재 binding 검사를 적용한다. 구조 PASS를 의미적 완전성으로 보고하지 않는다.

restore는 최초 잠정 해석/발견 후 미평가/intent만/관측 후 미평가/평가 후 미반영/
충분 처리/중요 변경을 구분한다. 현재 identity·goal·관측·종료 범위를 대조하고 유효
결과를 재사용한다. 복원으로 미평가나 선호 미확정을 확정하지 않는다. 과거 거부·실패를
남긴다. 검증은 제품 이름 대신 필요한 대조→관측→판정→행동→반영·종료 변화를 관측한다.
선언 fixture, 작성 호스트 관측, 독립 행동 검증, 실제 목표 충족을 각각 보고한다.

### 추천 전달과 유효 판단의 재대조 (§§27.13–27.14)

충분한 내부 비교 뒤 현재 목표에 가장 적합한 조합 한 가지를 먼저 제시한다.
주요 선택 도구·skill의 실제 이름을 직접 밝히고, 확인한 구체 기능·산출물·수행 주체·연결·선택 이유·조건·한계를 설명한다. 포괄적인 판단 지침이라는 표현만으로 이름이나 핵심 기능을 대신하지 않는다. 반환 전 현재 SelectedAssets/Architecture 및 학습 결과와 대조하여 중요한 능력과 필요한 호스트 변환이 빠지거나 자동 실행으로 과장되지 않았는지 확인한다. 특정 제품의 채택을 고정하지 않으며 대안 조합과 실행 순서를 구분한다.
조건부 결과·사용자가 요청한 비교는 보존한다. 다른 방향의 추천 필요 여부는 결과
확장 선호로만 선택적으로 물으며, 필수 탐색·심화·판단을 사용자 응답으로 미루지 않는다.

닫힌 해석의 소비자 버전이 바뀌면 원래 답·능력·범위·두 경로가 여전히 유효한지
먼저 대조한다. 의미 변경·반박·중요 공백이면 실제 변경/재학습 계약으로 처리한다.
내용은 그대로라면 execution-interface의 SIMPLIFY interpretation_rebind로 현재
소비를 새로 관측·평가하고 원래 학습과 구분해 적용한다. 학습을 다시 예약하거나
복제 실행으로 동일 판단을 재작성하지 않는다. 현재 Review·Gate와 미완료 의무는
유지한다. 일부 경로 절감을 전체 응답 시간·의미적 품질 개선으로 보고하지 않는다.
